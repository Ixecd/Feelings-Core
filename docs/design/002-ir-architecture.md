# ADR 002: 四层 IR 架构

> 状态：已定稿（修订：2026-06-17 — v0.3 全链路落地后对齐实现态）
> 日期：2026-05-26
> [Core] PSIR/DSIR/ESIR 三层归属 Feelings-Core (运行时)。Anim 只输出 FSIR。Core 未出生前由 Anim 暂代。

---

## 动机

为什么是四层 IR（FSIR → PSIR → DSIR → ESIR），不是三层，不是五层。

传统编译器通常有两到三层 IR（AST → HIR → MIR → LIR）。但 animi 不是编译器——它是交织器。每层 IR 不是在降级抽象——是在织入一股新的独立流。层数由独立流的股数决定，不由抽象层次决定。

---

## 决策

四层 IR。每层织入一股不属于前面任何一股的外部变量。

### FSIR — 感受结构层（与前人无关，与具体设备无关）

```
织入的流    感受语义。主旋律、点缀配比、形状、强度区间。
没有织入    个人生理参数。设备分配。帧级指令。

为什么这一层要独立：
    同一个 .anim 源码可以由不同的人使用。同一份 FSIR——
    不同的人上 PSIR 不同。不同的设备上 DSIR 不同。
    FSIR 是感受结构的"通用本体"——不绑定任何具身实现。
```

### PSIR — 个人适配层（PBM 左乘）

```
织入的流    个人基线矩阵（PBM）。四维差异化冷启动系数
            （内脏 0.75 / 情绪 0.40 / 触觉 0.80 / 听觉 0.85）。
            防御激活层级（DefenceLevel D1/D2/D3）——不是"创伤分类"——
            是等控器自身的 VSA 相变标记——非叙事驱动。
            强度 cap。非线性 sigmoidal 缩放。
            跨维度阻尼矩阵（DampingMatrix + DampingState）。
            冷启动守护（ColdStartGuard——前 N 次 Session 强制关闭预测器）。
            脱敏检测（信号变异度——连续停滞 → degraded）。
            时域漏桶（NeuroEnergyTracker——四维独立漏桶 + 非线性泄漏
            + 不应期保护窗 + 跨维度耦合 σ + 全局桶）。

为什么不能和 FSIR 合并：
    PBM 永不离设备。FSIR 是共享的——可以缓存在服务器上。
    如果 PSIR 和 FSIR 合并 = 个人生理数据需要离开设备才能生成 IR。
    违反了 Feelings 的隐私红线——"原始数据永远不离开用户设备"。

    所以 FSIR → PSIR 这一步必须在设备本地完成。
    不是性能优化——是隐私架构的硬约束。
```

### DSIR — 设备分配层（算力感知交织）

```
织入的流    设备组合。缺失降级。信号编码。

v0.3 实现态：
    当前骨架——设备集 {ear} only 硬线。ear 缺失 → 拒绝编译。
    wrist / neck / temple 缺失 → 降级标记（v0.4+ 完整设备集启用）。
    .anim → .dsir.json 端到端跑通。


为什么不能和 PSIR 合并：
    设备集合是可变的——同一用户这次戴着腕部，下次没戴。
    同一份 PSIR → 不同设备组合 → 不同 DSIR。
    如果合并 = 每次设备变化需要重算 PSIR = PBM 每次都要重新参与。
    分离 = 设备降级不影响个人适配层的缓存命中。
```

### ESIR — 执行信号层（闭环反馈）

```
织入的流    上一帧生理反馈（v0.5+）。偏差修正量（v0.5+）。
            安全插桩激活状态（flags bit0/bit1/bit2）。

v0.3 实现态：
    6 种预定义 shape 时间轴展开。
    Postcard 二进制输出——16B 固定宽度帧结构。
    .anim → .esir 端到端跑通（90 帧 calm 示例）。
    闭环偏差修正 + FPGA 对接 → v0.5。

为什么不能和 DSIR 合并：
    DSIR 是静态的——一个 session 内设备组合不变。
    ESIR 是帧级的——每 1ms 根据上一帧生理反馈重新参数化。
    DSIR 可以预计算并缓存。ESIR 必须在 FPGA 上硬实时生成。
    合并 = ESIR 的 1ms 帧级循环需要每次重跑 DSIR 的设备映射——
    白耗算力。且延迟翻倍。
```

---

## 层数证明——为什么不是三层或五层

```
三层方案（FSIR → PSIR → ESIR）：
    砍掉 DSIR → 设备缺失逻辑要塞进 PSIR 或 ESIR。
    PSIR 塞 → 个人适配和设备分配耦合 = 设备一变 PSIR 要重算。
    ESIR 塞 → FPGA 每一帧跑设备分配 = 延迟超标。

五层方案（加一层 TSIR——时间信号 IR）：
    有人提过在 ESIR 之上加一层时序调度层。
    但 shape 曲线的时间展开已经在 Pass 8 CodeGen 的自适应帧密度里完成。
    加一层 = 多一次序列化/反序列化 = 每帧开销不是零。
    否决。不因为不好。因为热路径不加层。
```

---

## 和 Feelings 安全模型的咬合

四层 IR 各自独立——安全校验在最前面的 PSIR 层完成。PSIR 之后的 DSIR 和 ESIR 不再做安全判断——只做信号分配和帧级执行。这和 Anim 的安全哲学一致：安全死在交织期。

当前实现态（v0.3）的安全体系——全部在 Pass 6 Personalize（PSIR 生成层）和 Pipeline Hook 中：

```
漏桶         NeuroEnergyTracker — 四维独立累积 + 非线性泄漏 + 不应期。
脱敏         信号变异度检测 — 连续 500 帧 δ<2 → degraded。
阻尼         DampingMatrix — 梯度 > 阈值×步长 → 冻结受影响的维度。
冷启动       ColdStartGuard — 前 N 次 Session 关闭预测器。
低锚保护     low_anchor_cap — R<0.3 → cap 硬上限 20。
强度缩放     sigmoidal + user_cap — 非线性压缩 + cap 二次校验。
oi 平滑      OiSmoothing — 强度 ≤ 20 硬截断 / >20 非线性衰减序列。
跨维度耦合   σ 系数 + 全局桶 — 单维度合法但总量超限时熔断。
```

全部在 Hook 架构下运行——每条防线独立可启用/禁用（`config.hooks`）。

详见 ADR 011/012/013/014/015。

---

*四层不是因为喜欢四。是因为有四股独立的流必须在不同的时刻被织进去。加一层 = 加延迟。减一层 = 两股不应该耦合的流被迫耦合。四层。刚好。一帧不差。v0.3 之后——四股流被拆成一帧一帧的 ESIR。——刚好。一帧不差。*
