# ADR 003: 九 Pass 交织管线（Pass 0-8）

> 状态：已定稿
> 日期：2026-05-26
> [Core] Pass 3/4/6/7/8 归属 Feelings-Core (需 PBM + Session + 设备)。Pass 0-2/5 归属 Anim。Core 未出生前由 Anim 暂代全部。

---

## 动机

为什么是八个 Pass，不是六个，不是十个。每个 Pass 的划分依据是什么。

---

## 决策

九个 Pass（Pass 0-8）。从 0 开始编号——和传统编译器对齐认知。Pass 0 是词法语法（和传统编译器对齐认知）。划分依据是**每个 Pass 只做一件事——织入一股新的信息流或施加一层新的安全约束**。

### Pass 0: LexParse — 源码 → Token → AST

```
为什么独立：
    所有后续 Pass 的输入。语法错误在 Pass 0 就死了——不进管线。
    和传统编译器的词法语法层完全同构——不需要重新设计。
    唯一的不同：不是 Token → AST → HIR，是 Token → AST → FSIR。
    但解析不关心后面的 IR 层。Pass 0 自己独立。
```

### Pass 1: TypeCheck — 感受类型校验

```
为什么在 Pass 0 之后、安全层之前：
    Pass 0 只保证语法正确。不保证语义正确。
    "平静"和"explosion"在 .anim 源码里都是合法 token。
    Pass 1 查 Pattern Registry——平静存在。explosion 不存在。
    → 编译错误。不生成后续 IR。

    设备前置告警也在这里——不是安全错误，是降级标记。
    创作者需要知道"后颈设备未连接 → 本体感受维度将降级为 outline"。
    这是类型级的信息——和后颈有没有信号不是同一层。
```

### Pass 2: StaticSafety — 源码级安全规则（不依赖用户上下文）

```
为什么在 TypeCheck 之后、UserState 之前：
    能在不查用户档案的前提下判定安全的——先判。不留到需要用户上下文。
    强度等比缩放、点缀配比上限、形状约束、组合爆炸防护——
    全部不需要知道"这个用户是谁"。只需要知道"这个源码长什么样"。

    能在这一层拒绝的 → 不生成后续任何 IR。
    信号还没开始生成。安全零伤害。
```

### Pass 3: UserStateSafety — 源码 × 用户上下文

```
为什么不能和 Pass 2 合并：
    Pass 2 不要用户上下文 → 可以离线跑。可以缓存。
    Pass 3 需要创伤分型、cap、未成年标记——
    这些都是用户数据。永不离设备。
    合并 = 离线安全缓存不可用 = Session 启动延迟暴增。

    防御激活在这一层生效。
    创伤原子黑名单——禁主不禁点。
    这些判断不可能是"通用源码级"的——必须读用户档案。
```

### Pass 4: RuntimeGuard — 交织期预埋，运行期激活

```
为什么不放在"运行期"：
    运行期安全插桩不是在运行时才生成——是在交织期预埋的。
    Pass 4 做的事情不是判断——是生成判断代码。
    真正的判断在 ESIR 层由 FPGA 的寄存器比较完成。

    和 Pass 2/3 的根本区别：
        Pass 2/3 → 交织期直接拒绝。信号不生成。
        Pass 4 → 交织期不拒绝。生成带安全栅栏的信号。
        栅栏是交织期放的。触发器在运行期等一个不需要判断的比较。
```

### Pass 5: FSIRGen — AST → 感受结构 IR

```
为什么在安全层之后才生成 FSIR：
    安全校验在前 → 不通过的直接死在生成之前。
    通过的 AST 才进入 FSIR 生成——FSIR 里全是"已经安全"的信号结构。

    保留原始语义锚点：
        origin_shape: "gradual_rise_fall" — 即使已转为毫秒数值。
        origin_intensity: [15, 45] — 等比缩放前的原始区间。
        不是给信号层用的——是给逆向调试和语义复盘用的。
        FSIR 不只是一组数值。是"这个感受包被设计成什么样"的完整声明。
```

### Pass 6: Personalize — FSIR → PSIR（PBM 左乘）

```
为什么是独立的 Pass：
    PBM 永不离设备。
    PBIR 左乘发生在设备本地——不在 Server 端。
    Pass 0-5 可以完全离线。Pass 6 必须在设备端——用户穿戴并开始 Session 的那一刻。

    非线性 sigmoidal 查表（不是固定线性乘子）：
        低强度 ≈ 线性。中强度响应趋缓。高强度接近饱和。
        不是 0.5 × 0.7 = 0.35 的固定公式。
        是查表：0.5mA → PBM → 此人实际生理响应曲线 → 0.38mA。
        每个人的同一种神经纤维在相同的起点上反应不同。
```

### Pass 7: DeviceMap — PSIR → DSIR

```
为什么在 Personalize 之后：
    必须先知道"此人的平静需要多少迷走神经刺激"——再知道"哪个设备发这个信号"。
    反过来的话 = 先分配设备再适配个人 = 设备参数是通用值 = 没适配。

    算力感知交织在这一层：
        入门设备仅耳后 → 只生成迷走神经参数。
        高端全套 → 生成纺织物多点位阵列 + 温度场梯度。
        交织产物大小 ~2KB-24KB/帧。不提前知道设备组合——算不好。
```

### Pass 8: CodeGen — DSIR → ESIR

```
为什么是最后一层：
    前面的所有层都在描述"这个信号应该是什么"。
    ESIR 是"这一帧这个设备的具体物理参数"——
    电流、频率、脉宽、温度、振动幅值、时间戳（微秒精度）。

    自适应帧密度：
        rise 段 1ms/帧。peak 段 1ms/帧。fall 段 5ms/帧。plateau 段 10ms/帧。
    安全校验帧不受自适应影响——每 N 帧必须嵌入一个校验点（N 固定）。

    闭环预修正——不是等偏差来了才调：
        预测器输出 ŝₜ₊₁ → 回读 |rₜ - ŝₜ| → 注入预修正。
        不等下一帧才开始调。这一帧已经加上了上一帧的误差补偿。
```

---

## Pass 数量和性能边界

```
为什么不是 4 个 Pass：太粗。安全层混在一起 → 缓存命中率低。
为什么不是 12 个 Pass：太细。每层一次序列化 → 延迟累积。
8 个 Pass + 双流水线 → 前台只有 Pass 6-8。后台处理 Pass 0-5。
用户感觉不到的延迟 = 后台已经跑完了。感知零。
```

---

*八个 Pass。不是因为喜欢分。是因为每一股独立流——源码、类型、安全、用户、执行——在被织进绳之前都不应该和别的流混在一起。混在一起不是优化——是在管线里同时跑安全校验和用户适配。两件事一个要设备空闲、一个要用户穿戴——它们不在同一帧里发生。分开才跑得动。*
