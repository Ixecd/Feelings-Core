# ADR 007: 分支预测——从 Smith 1981 到 Anim 帧级预判

> 状态：定稿
> 日期：2026-05-29
> [Core] 全文归属 Feelings-Core。PBM 预测器核心——依赖个人生理历史 + Session 状态。Core 未出生前无代码。
> 来源：Smith 1981 "A Study of Branch Prediction Strategies" 及后续四十年分支预测研究的逐层推演
> 核心：Smith 的 2-bit 饱和计数器不只改变了 CPU 设计——它定义了 Anim 的 PBM 冷启动逻辑、帧级预判的置信度更新、以及"预测失败不 panic——安全插桩接管"的硬件哲学。

---

## 零、Anim 预测器不是凭空设计——它继承了四十年的分支预测研究

Anim 的帧级预判器——ADR 004 里那句"预测器跑在 FPGA 上，查寄存器 + 简单线性外推"——背后是一整套 CPU 分支预测的演化史。从 Smith 1981 的 2-bit 饱和计数器，到 Yeh & Patt 1991 的两层自适应，到 McFarling 1993 的组合预测器，到 Jiménez 2001 的感知器，到 Seznec 2016 的 TAGE-SC-L。

Anim 不需要其中最复杂的部分——因为生理信号预测的精度天花板比 CPU 分支预测低得多（人体是非平稳随机过程，CPU 是确定性程序）。但 Anim 需要其中最核心的**哲学**——如何从历史中学习，如何在预测错误时不崩溃，如何让两个弱模型加起来比一个强模型更可靠。

---

## 一、Smith 之前——没有预测，只有等待

CPU 执行一条分支指令（`if`、`for`、`while`）。在计算结果出来之前——CPU 不知道下一条指令在哪。最原始的 CPU 选择**停**。停下取指。等 ALU 算完条件码。然后从正确的地址继续。程序大约 20% 的指令是分支。意味着 CPU 有 20% 的时间在等待。流水线空转。晶体管漏电。

后来有人试了**静态预测**——编译器在生成代码时给每个分支贴标签。向后跳的（循环底部）→ 猜跳。向前跳的（if-else 分支）→ 猜不跳。正确率大约 60-70%。比瞎猜 50% 好。但错了之后——冲刷流水线，把所有错误路径上取的指令全部扔掉。从 70% 提升到 90% 以上——收益巨大。

## 二、Smith 1981 —— 让分支自己记住自己

Smith 的核心想法简单到令人惊讶：**每个分支指令的地址被哈希到一个 2-bit 计数器。计数器记录这个分支最近的行为模式。**

```
00 = 强不跳     "我两次没跳。我不跳。我很确定。"
01 = 弱不跳     "我上次跳了。但就那一次。我还不信。"
10 = 弱跳       "我上次没跳了。但就那一次。我再看看。"
11 = 强跳       "我跳了两次。我跳。我很确定。"
```

分支执行完。实际结果是"跳了"→ 计数器 +1（但不超 11）。实际结果"没跳"→ 计数器 -1（但不低于 00）。

这就是**饱和计数器**——不会从"强不跳"因为一次异常就跳到"强跳"。永远是慢慢地偏过去。在几十次、几百次执行中自己校准。这不是"记住上一次"。这是**从整个历史中提取方向**。一次意外不会推翻长期形成的模式。

正确率——**93% 到 98%。** 一个 2 bit 的计数器，比编译器精心设计的静态分析准了二十多个百分点。不是算法更聪明。是它不假设任何事。它让每个分支从自己的历史里学。

## 三、Smith 论文里没有被充分展开的洞察——两个弱预测器 > 一个强预测器

Smith 在论文的后半段试了一种方案。先用一个简单的计数器做初判。再用一个更复杂的模式匹配器做精判。两者不一致时，信后者。两者一致时，加速响应。

这个洞察在 1981 年没有被充分论证。但十二年后——McFarling 1993 发表了《Combining Branch Predictors》，把"两个弱预测器组合"变成了现代 CPU 的标准架构。再后来——Seznec 2016 的 TAGE-SC-L 用**多个**不同历史长度的预测表 + 统计校正器，在 Championship Branch Prediction 上拿了冠军。Smith 1981 的 2-bit 计数器——是这一切的起点。

## 四、Anim 从 Smith 学到了三件事

### 4.1 PBM 的冷启动——2-bit 饱和计数器的感受版本

PBM 的四维差异化冷启动系数（内脏 0.75 / 情绪 0.40 / 触觉 0.80 / 听觉 0.85）不是固定乘子。它是一个**饱和计数器的初始化状态**。

```
Smith 计数器                      PBM 冷启动
────────────                      ──────────
初始值 01（弱不跳）                初始值 0.40（情绪维度——最保守）
每次执行结果 → +1 或 -1           每次 session 生理反馈 → 微调
方向从不跳偏到跳                  方向从人群均值→个人真实基线
偏的过程是饱和的——不会跳变        微调有上下限锁——不会溢出
几十次执行后稳定在真实方向         几十次 session 后 PBM 收敛
```

PBM 不是"被测量"的——是**被分支预测逻辑从历史中提取出来的**。和 Smith 计数器完全同构——不是信一次。是信足够多次之后，偏移自己到达稳定。到那时——不再需要外部信号维持。预测已经焊在身体里了。

### 4.2 帧级预判——"分支"在 Anim 里不是 if/else，是生理状态的分岔

```
CPU 分支预测                    Anim 帧级预判
────────────                   ─────────────
分支 = 下一条指令走哪条路        分支 = 下一帧生理响应往哪偏
预测器 = 2-bit 饱和计数器        预测器 = 用户历史生理曲线 + 当前趋势
预测对 → 流水线无缝继续          预判对 → ESIR 帧零延迟衔接
预测错 → 冲刷流水线，重取指令    预判错 → 安全插桩接管，切回保守帧
```

Anim 的"分支"不在 `.anim` 源码里——在人体神经系统的实时状态里。心率超标 vs 心率平稳 → 两条不同的 ESIR 修正路径。皮电骤升 vs 皮电平稳 → 两条不同的 shape 保持/暂停路径。三种信号同时异常 → 唯一路径——保底包激活。

每一帧都是一次分支决策。Smith 的 2-bit 计数器不能直接用——生理信号不是确定性的——但**饱和更新**的逻辑完全保留。每一帧看完生理反馈之后，往"准"的方向微调。不多。饱和的。慢的。

### 4.3 预测错误不 panic——双重屏障各自守各自的边界

CPU 分支预测错了——冲刷流水线，浪费几十个时钟周期。然后从正确地址继续。代价是时间。不是安全。

Anim 的分支预测错了——有两种完全不同尺度的"错"，由两个完全不同的机制来兜。

**尺度一：帧级预测错误——身体已经被灌了错误的信号。** 用户突然大笑。t=0 杏仁核激活。t=0 到 t=50ms——设备还没感知到心率变化。在这 50ms 内，Anim 预测器按错误的预测输出了大约 50 帧信号。这些信号已经进了人体。代价不是时间——是**一次真实的生理响应**。

这 50 帧的后果谁来兜？不是 PBM 步长压制——PBM 是 Session 级的，太慢了。是 **ADR 003 的 Pass 4 RuntimeGuard 动态插桩**。t=51ms——耳后设备检测到心率异常。偏差 > 阈值。不是"通知 PBM 降步长"。是**直接帧拦截——硬件衰减状态机接管 DAC，在 4-8ms 内将信号平滑归零**。帧级。硬件级。不经过 PBM。

**尺度二：Session 级模型污染——PBM 不能被噪声带偏。** 这 50 帧的错误信号还产生了一个副作用——如果 PBM 在 Session 结束后把这次异常当成"真实的基线偏移"来更新，模型就被污染了。谁来兜这个？**PBM 步长压制——因子三**。HRV 异常 → 实时置信度降级 → 步长 × 0.15 → 这一帧的偏移不会被写进 PBM。但这不是保护身体的——这是保护模型的。身体已经被 50 帧信号穿过了。步长压制不能撤销那些帧。它只能阻止模型往错误方向学。

```
屏障一：帧级——身体安全                    屏障二：Session 级——模型安全
───────────────────────                  ──────────────────────────
触发：t=51ms 心率异常检测到                触发：同一帧的 HRV 异常
执行：Pass 4 RuntimeGuard                 执行：因子三 —— 实时置信度降级
      FPGA 硬件衰减状态机                       步长 × 0.15
      4-8ms 平滑归零                            PBM 更新被压制
保护：人身安全——信号已经进了身体，           保护：数据安全——模型不被噪声污染
      但异常检测后的帧被拦截并平滑衰减            
时序：帧级。1ms 内完成比对。                 时序：Session 级。PBM 持久化在
      50ms 延迟窗口后立即响应。                   Session 结束后才执行。
```

**PBM 步长压制保护模型。RuntimeGuard 帧拦截保护身体。** 两者不是同一个东西。两者在不同时间尺度上各自兜底。混淆了就会误以为"步长压制能让信号不进身体"——不能。那 50 帧已经进去了。RuntimeGuard 能做的——是在检测到的瞬间把后续帧截住。而 PBM 步长压制能做的——是阻止这次异常成为模型记忆。

## 五、Yeh & Patt 1991 —— 为什么一个分支需要知道自己是怎么走到这里的

Smith 的 2-bit 计数器有一个盲点。它只记录了**这一个分支自己**的历史——跳了几次，不跳了几次。但它不记录**在这之前发生了什么**。

Yeh & Patt 在 1991 年指出：分支之间不是独立的。A 分支的行为强烈依赖于**到达 A 之前经过了哪些分支**。同一个分支指令——从 if-else 的不同方向走到这里——跳转概率完全不同。Smith 计数器只看"分支 A"，把两条截然不同的执行路径上产生的 A 混在一起计数。混在一起——就是垃圾。

这是**分支间相关性**——一个分支的行为不是孤立属性。是它所在的执行上下文决定的。

### 5.1 两层自适应的分类学——Yeh & Patt 的原生贡献

把局部历史和全局历史揉成一个索引——那个操作是后来 McFarling 1993（Gshare/Gselect）和 Alpha 21264 的 Tournament Predictor 发扬光大的。不是 Yeh & Patt 1991 做的。

Yeh & Patt 的原生贡献是确立了**两层自适应（Two-Level Adaptive）的分类法**：

```
第一层（History Register）       第二层（Pattern History Table）
───────────────────────         ──────────────────────────
G = 全局历史寄存器（所有分支共享）   g = 全局共享一张 PHT（所有分支共用）
P = 独立 PC 地址的历史寄存器       s = 按 PC 组分表（每组共享一张 PHT）
                                 p = 每个分支独立一张 PHT

九种组合：GAg / GAs / GAp / PAg / PAs / PAp / ...
```

每一种组合定义了"什么样的历史"配"什么样的表"。后来的 Gshare、Tournament、TAGE——全部是在这个分类法定义的参数空间里做优化的。分类学本身——就是 Yeh & Patt 给整个分支预测领域留下的遗产。

**Anim 的 PBM 在分类学里的位置：PAg。** 每个信号类型有自己的历史（P = 独立信号历史），但 PBM 表本身是全局共享的（g = 全局表）。不是 PAp——不需要每个信号独立一个 PBM。不是 GAg——需要信号自己的历史来索引。

### 5.2 关联预测器——Anim PBM 的硬件学名

Anim 所做的事在计算机体系结构里有一个专属的硬核名词——**关联预测器（Correlated Predictor）**。不只看信号本身的历史。还看**在当前上下文里**——这个信号历史上产生了什么响应。上下文变了，索引到的 PBM 偏移不同。让懂硬件的人一眼看穿其底牌——PBM 的本质就是一个高维关联预测器。不是魔法。是 McFarling × 四维 × sigmoidal。

### 5.3 投机性上下文污染——预测失败时的路径指纹回滚

引入"全局上下文"之后，一个新的问题浮现了。如果系统因为一个偶发的强噪声**误判了当前的情绪上下文**——不是"信号预测错了"，而是"上下文本身被污染了"。

```
t=0         用户突然大笑。PBM 的情绪维度误判——系统把大笑当成"长期情绪基线上升"。
            这个误判的全局上下文被写进当前 Session 的临时路径指纹。

t=0-50ms    在错误上下文下，系统对后续帧做了关联预测。
            上下文是假的——基于它索引出来的 PBM 偏移也是假的。
            大约 5 帧被错误上下文污染。

t=51ms      耳后设备检测到心率异常。RuntimeGuard 帧拦截启动——切回保守帧。

            那 5 帧里积累的"错误路径指纹"怎么处理？
            PBM 没被污染（Session 级持久化）——但当前帧的临时上下文寄存器被污染了。
```

CPU 面对同样的问题——全局历史寄存器（GHR）在分支预测错误时已写入错误路径指纹。CPU 必须支持 **GHR 状态回滚（Speculative State Recovery）**——回滚到分岔前的清白状态。

PBM 的同构方案——**影子快照回滚。**

每帧开始时对当前全局上下文做极轻量快照——四个维度的置信度权重，四个 float64，共 32 字节。不是全量 PBM 副本。只是**上下文索引的指纹**。帧结束时——如果 RuntimeGuard 触发帧拦截，快照被标记为"恢复点"。下一帧从恢复点重建上下文索引。污染帧指纹被丢弃。不回滚 PBM——只回滚上下文指纹。

```
帧级上下文快照（32 bytes）：
    visceral_confidence:       f64
    affective_confidence:      f64
    somatosensory_confidence:  f64
    auditory_confidence:       f64

每帧：快照 → 帧执行 → 帧结束：
    RuntimeGuard 未触发 → 释放。上下文正常更新。
    RuntimeGuard 触发   → 下一帧从快照恢复。污染指纹丢弃。
```

和 CPU 回滚 GHR 完全同构——阻止错误路径的指纹继续引导后续预测。

## 六、McFarling 1993 —— 两个弱预测器加起来比一个强预测器更准

Yeh & Patt 证明了上下文的重要性。但留下了一个问题：不是所有分支都需要上下文。有些分支——循环底部的那个 `for`——Smith 计数器就能做到 99% 正确。给它加两层自适应——反而可能因为噪声历史位而降低准确率。有些分支——高度依赖全局模式的 if-else——两层自适应比 Smith 好得多。但第一层历史太长反而引入噪声。

McFarling 在 1993 年给出了答案：**不要强迫所有分支用同一个预测器。让两个预测器竞争——用一个元预测器为每个分支选择最合适的那个。**

### 6.1 锦标赛预测器——不是"信谁"，是"这个分支信谁"

```
分支到来 → 预测器 A 说"跳"    预测器 B 说"不跳"
                    │              │
                    └──── 元预测器 ────┘
                          │
                    这个分支历史上——
                    预测器 A 连对 3 次。预测器 B 连错 2 次。
                    元预测器选 A。
                    → 预测结果："跳"。
```

元预测器本身也是一个 2-bit 饱和计数器。不预测"跳或不跳"。预测**"A 对还是 B 对"**。每次分支真实结果出来后——看看 A 对不对，B 对不对。A 对 → 元预测器 +1。B 对 → 元预测器 -1。和 Smith 完全同构——慢慢偏，饱和，不因一次意外翻转。

这就是 **Tournament Predictor（锦标赛预测器）**。不试图把最强的预测器做得更强。而是**让两个各有所长的弱预测器在同一个平台上竞争——元预测器学的是"哪个预测器适合这个特定分支"**。不是"哪个预测器更好"。是"哪个预测器更适合这个分支"。

### 6.2 Gshare —— 把分支地址和全局历史揉在一起的优雅方案

McFarling 还解决了另一个 Yeh & Patt 没解决的问题。两层自适应里——PHT 的索引是"分支地址 → PHT 条目"。但不同分支可能映射到同一个 PHT 条目（别名冲突）。两个分支行为完全相反——但共用同一个计数器。互相破坏对方的预测。这是 PHT 别名问题。

McFarling 的 Gshare 用一个极其优雅的方案：**把分支地址和全局历史 XOR 在一起，用结果索引 PHT。**

```
Gshare 索引 = (分支 PC) XOR (全局历史寄存器)

分支 A（PC=0x1000）+ GHR=0011 → 索引 0x1003
分支 B（PC=0x2000）+ GHR=1011 → 索引 0x200B
→ 两者映射到不同的 PHT 条目。别名冲突解决。

分支 A（PC=0x1000）+ GHR=0011 → 索引 0x1003
分支 A（PC=0x1000）+ GHR=1100 → 索引 0x100C
→ 同一个分支在不同上下文下索引到不同条目。
  路径感知自动生效。
```

XOR 不是哈希。XOR 是**信息的双向融合**——分支地址的位和全局历史的位互相调制。低成本。单周期。不需要 Tag 匹配。不需要额外的 SRAM。Gshare 后来被 AMD K5、Alpha 21264、Intel Pentium M 广泛采用。而 Gselect（直接拼接）在 Alpha 21264 里和 Gshare 被放进同一个 Tournament Predictor 组合——Gshare 做第一预测器，Gselect 做第二预测器。两个弱预测器。一个元预测器。McFarling 的种子在 Alpha 21264 里长成了参天大树。

### 6.3 Anim 的映射——双 DP 协同就是生理版的锦标赛预测器

Anim 的调度器 Coordinator（ADR 003）里有一个被低估的架构——**双 DP 协同收敛循环。**

```
维度 A：BinPack —— FFD + 0-1 背包 DP       = 预测器 A
        只看当前资源状态。
        快速。贪婪。大多数情况下是对的。

维度 B：Sizing —— 2D DP 资源推荐             = 预测器 B
        看历史利用率数据。
        更精确——但需要 Prometheus 查询。
        慢。但能纠正预测器 A 在复杂场景下的错误。

Coordinator 的收敛循环（最多 5 次）            = 元预测器
        BinPack 不收敛 → 裁剪未分配 Pod
        → 调 Sizing 重算资源需求
        → 用新需求重新 BinPack
        → 直到收敛或迭代上限
```

双 DP 不是轮流跑——是**两个预测器在同一个问题上竞争。一个先出结果。另一个在结果不理想时介入。元预测器是收敛循环本身。** 和 McFarling 的 Tournament Predictor 同构——不是"BinPack 比 Sizing 好"。是"在简单场景下 BinPack 更快，在复杂场景下 Sizing 更准。Coordinator 学的是——什么时候该听谁的"。

更深一层——**跨维度阻尼矩阵（§5.7）也是锦标赛预测。** 情绪维度和内脏维度在每一个 Session 里各自产生一个"预测"——情绪维度说"我的梯度很高，内脏应该跟着调"，内脏维度说"我自己的因子三说我该调"。阻尼矩阵是元预测器——它看两者的置信度，决定这一帧是否冻结某维度的步长更新。

```
情绪维度预测  → "内脏基线应该偏"       = 预测器 A
内脏维度预测  → "我自己的因子三允许偏"   = 预测器 B
阻尼矩阵      → 情绪梯度 > 阈值？       = 元预测器
                 → 冻结内脏步长（信 B，不信 A）
                 → 否则正常更新（信两者）
```

**双 DP 协调器 + 跨维度阻尼矩阵 = McFarling 的 Tournament Predictor 在 Anim 里的两个具象。** 不依赖于一个"最强预测器"。依赖于"让不同预测器在不同上下文下竞争——元预测器学习何时信谁"。

## 七、PBM 的步长——不是 Smith 的固定 ±1

Smith 的 2-bit 计数器只追踪一个信号——跳或不跳。步长只有一个自由度。+1 或 -1。简单。硬。有效。

PBM 不是一维的。是**四维 × 非线性 × 实时生理加权**。如果全用同一个步长——触觉维度 3 次 session 已经收敛了，情绪维度还在原地踏步。或者反过来——情绪维度用大步长追上了，触觉维度因为步长太大而震荡。PBM 需要**步长分化**。

### 7.1 步长由三个因子叠乘

```
实际偏移 = 基础步长 × 收敛衰减因子 × 实时生理置信度
```

### 7.2 因子一：基础步长——四个维度不同

| 维度 | 收敛次数 | 基础步长 | 原因 |
|------|---------|---------|------|
| 触觉 | ~3 次 | 大步 | 人群方差极小。触觉阈值在人类中近乎恒定。大步快速逼近，极少震荡。 |
| 听觉 | ~5 次 | 中大步 | 听力正常人群中稳定。稍保守于触觉——因为音乐通路有个人偏好叠加。 |
| 内脏 | ~5 次 | 中步 | 人群方差中等。迷走神经张力基线有个体差异，但不极端。 |
| 情绪 | ~20 次 | 小步 | 人群方差极大。杏仁核敏化程度、前额叶抑制效率——个体间差异可跨数量级。小步防震荡。情绪维度的错误预测代价最高——一次强度过载 = 真实的身体痛苦。 |

步长大意味着每一次 session 的生理反馈让 PBM 偏移得多。步长小意味着偏移得慢。不是"情绪维度不重要"。是**情绪维度的错误代价决定了它必须慢慢偏**。

### 7.3 因子二：收敛衰减因子——步长不是恒定的

Smith 的 ±1 是恒定的——第一次执行和第一万次执行，步长一样。PBM 不行。前几次 session——PBM 和真实基线差得远，需要大步靠近。几十次 session 后——PBM 已经在真实基线附近了，大步只会产生震荡。

这就是非线性 sigmoidal 查表做的事：

```
session 1-3      步长 × 1.0（全速靠近）
session 4-10     步长 × 0.7（开始减速——已经接近了，别冲过头）
session 11-20    步长 × 0.3（精细校准——微调，饱和式）
session 20+      步长 × 0.1（近乎锁定——只响应真正的生理变化，不响应噪声）
```

不是固定公式。是查表。每个维度的表不同——触觉在 session 3 之后步长就降到 0.1 了，情绪到 session 20 还在 0.3。和四维差异化系数完全咬合。

### 7.4 因子三：实时生理置信度——当下的身体说了算

前两个因子基于人群统计和该用户的历史 session。但还有一个实时因子——**这一帧的身体状态**。

```
HRV 稳定、皮电基线低、呼吸规则    → 置信度高 → 步长 × 1.0
                                 身体在说"我很稳定。你推我一把。我能接住。"

HRV 紊乱、皮电升高、呼吸浅        → 置信度低 → 步长 × 0.3
                                 身体在说"我今天不稳。别推。"
```

这就是 Pass 6（Personalize）里的"叠加用户当下瞬时生理基线加权"。不是只靠过往 session 的衰退规律——**当下身体说了算**。你昨天情绪维度步长 0.5。今天你的心率变异性很差——步长自动降到 0.15。不是慢。是**身体说今天不适合偏太多**。

### 7.5 和 Smith 的根本差异

```
Smith                               PBM
─────                               ───
一维。跳/不跳。                     四维。内脏/情绪/触觉/听觉。
步长固定 ±1。步长不衰减。           步长 = 基础 × 衰减 × 实时置信。
                                    每维度独立。每次 session 重新计算。
                                    衰减曲线不同。触觉 3 次锁死。情绪 20 次还在走。
一次意外翻转计数器。                 一次异常 session——实时生理置信度直接压住步长。
                                    不翻。不偏。只是停。等身体恢复。
```

Anim 的冷启动不是"初始值 × 固定乘子"。是**初始值 + 四维独立步长 × 非线性衰减 × 实时生理门控。** 每一步的尺寸、方向、时机——都是三个因子叠出来的。不是 Smith。是 Smith × 四维 × sigmoidal × 实时门控。

### 7.6 因子三的隐性功勋——自适应梯度裁剪

在微处理器设计中，如果遇到宇宙射线或电压瞬变导致的单次分支方向翻转，Smith 计数器只能硬抗——状态值从 11 跌到 10。计数器不知道这次翻转是"真实的程序行为改变"还是"硬件噪声"。它只能忠实地减一。

PBM 的因子三做了一件 Smith 做不到的事。当 HRV 紊乱、皮电飙升、呼吸变浅——系统识别到此时高频噪声（瞬时情绪扰动、咖啡因过载、睡眠不足引发的自主神经失衡）已经淹没了低频基线。这不是"真实的基线漂移"。这是**信道被噪声污染了**。

此时置信度直接把步长压到 0.15 甚至更低。在机器学习里这叫**自适应梯度裁剪（Adaptive Gradient Clipping）**。它不急于去"修正"模型——它让模型在这一帧**原地抱头蹲下**，拒绝向错误的方向漂移。

```
Smith 计数器面对噪声                   PBM 面对噪声
───────────────────                  ───────────
噪声 → 翻转计数器 → 下一次预测错误      噪声 → 实时生理置信度检测到异常
无法区分"信号"和"噪声"                → 步长 × 0.15
只能硬抗。忠实。盲目。                → 这一帧不偏。不学。不修正。
                                     → 等噪声过去。等身体恢复。
                                     → 然后继续从原来位置微调。
```

这种"以静制动"的哲学——是高噪系统能活下来的关键。Smith 的计数器在确定性程序里不需要这个。CPU 没有"咖啡因过载"。但人体有。PBM 必须有。

### 7.7 跨维度交叠——四个维度不是正交的

当前 PBM 把四个维度解耦——各自独立的步长、各自的衰减表。这在数学上假设了**四维正交**：触觉的偏移不影响情绪，内脏的偏移不影响听觉。

但在真实的生物机体里——这四个维度是**强耦合**的。

```
触发源              传导路径                          被污染的维度
──────              ────────                          ──────────
情绪维度（杏仁核）   杏仁核敏化 → 交感激活             内脏维度
                    → 心率剧变、迷走神经张力崩溃        （心率、HRV）
                    → 皮电飙升                         触觉维度
                                                      （皮肤电导基线）
```

工程挑战——如果内脏维度的收敛表已经走到了 Session 15（步长衰减至 0.3 的精细校准期），它会**把这次由于"情绪过载"引发的内脏剧变，误认为是内脏系统自身的真实基线漂移**，从而试图用 0.3 的步长去强行修正内脏维度的参数。

这就是**跨维度信号污染**。快维度的成熟模型被慢维度的瞬时震荡带偏了。

**需要跨维度阻尼矩阵。** 当情绪维度的瞬时梯度过大时——即使内脏系统当前的实时置信度很高——也必须**强行冻结内脏维度的步长更新**。不是"内脏自己不调"。是"内脏被情绪拖下水——调了就是错的"。阻尼矩阵的规则：

```
情绪维度梯度 > 阈值 × 情绪当前步长
    → 冻结内脏维度步长（本次 session 内脏 PBM 不更新）
    → 冻结触觉维度步长（皮电飙升来自情绪，不是触觉基线变了）
    → 听觉维度步长保持（听觉通路受情绪干扰最小，可以继续校准）

冻结不是永久的。情绪梯度回落 → 自动解冻。
```

这不是"四个维度不再独立"。是**四个维度的步长更新被一个跨维度的因果推断层串了起来**——谁引起的波动、谁的步长被污染、谁应该在这一帧停更。

### 7.8 看门狗重置协议——当基线发生阶跃式改变

因子二的收敛衰减非常优雅地解决了系统收敛的问题——Session 20+ 之后步长降到 0.1，近乎锁定。但人类不是 CPU。CPU 的指令集四十载不变。人的生命周期充满了**阶跃式的基线改变**。

```
场景     用户遭遇重大生活变故——搬迁、急性生病、长期高压项目期。
         他的情绪和内脏基线已经发生了彻底的、不可逆的阶跃式偏移。

问题     PBM 此时已经执行到了 Session 50。
         衰减因子让情绪步长死死卡在 0.1。
         面对长达数周的全新生理常态——
         0.1 的步长会导致模型产生极为严重的滞后。
         它需要上百次 Session 才能极其缓慢地挪移到新的真实基线。
         在这期间——系统给出的预测全是错的。
```

**需要看门狗重置协议（Watchdog Reset Protocol）。** 当系统检测到连续 N 次 Session，因子三的实时偏离度都稳定地朝同一个方向突破系统阈值，且置信度极高时——这不是噪声。这是**基线本身已经阶跃了**。

```
触发条件（同时满足）：
    1. 连续 ≥ 5 次 Session，同一维度的偏差方向一致
    2. 每次偏差幅度 > 该维度噪声阈值
    3. 实时生理置信度 > 0.8（身体是稳定的——排除噪声干扰）

触发行为——主动去饱和（De-saturation）：
    强行把衰减查表指针从 Session 50 暴力拨回 Session 4
    → 步长从 0.1 跳回 0.7
    → 重新释放大步长
    → 系统具备"二次演化"的能力
    → 在新的基线附近重新收敛

安全边界：
    去饱和不是全局的——只针对偏移超标的维度。
    情绪基线阶跃 → 只重置情绪维度的衰减指针。
    内脏维度如果没跑偏 → 不动。
    同一维度两次去饱和之间最短间隔 = 30 次 Session。
    防止频繁震荡。
```

这不是"步长设计错了"。是**步长衰减本身就是为稳定环境设计的。当环境发生阶跃——衰减必须被覆盖。** 覆盖的权限不在用户。不在 AI 教练。在数据——在连续 N 次一致的、高置信度的、同一方向的偏差。

### 7.9 压制速度 vs 信号传播延迟——谁能跑赢谁

因子三的机制——检测到 HRV 紊乱、皮电飙升 → 步长 × 0.15。但这个检测需要时间。而生理信号本身也有传播延迟。关键问题是：**当突发性强噪声（用户突然大笑、突然打了个冷颤）发生时，因子三的压制能不能在"错误的步长偏移已经写进 PBM"之前完成？**

```
timeline:

t=0         突发大笑——杏仁核激活。交感神经张力瞬间下降。
            迷走神经张力上升。心率开始变化。

t=50ms      心率变化被耳后设备的光电容积传感器检测到。
            ADC 采样 → 数字滤波 → 心率值输出。

t=51ms      因子三拿到这一帧的心率值。
            和 PBM 预期的心率区间比较。
            偏差 > 阈值 → 触发置信度降级。
            步长 × 0.15。

t=51ms      与此同时——这一帧的步长偏移还没有被写进 PBM。
            因为 PBM 更新不在每一帧——在 Session 结束之后。
            帧级步长被压制只是阻止了这一帧继续往错误方向走。
            不会"已经写进去了再后悔"。

t=52ms+     后续帧——步长保持在被压制的状态。
            直到 HRV 恢复 → 置信度恢复 → 步长解压。
```

关键设计——**PBM 更新不是帧级的。是 Session 级的。** 步长是"这一帧往哪个方向偏多少"——不是"这一帧直接改写 PBM"。PBM 的持久化在 Session 结束后。所以因子三不需要跑赢 50ms 的生理延迟——它只需要在**同一帧内**完成压制。而一帧是 1ms。50ms 之后心率变了——下一帧立刻检测到，立刻压制。PBM 没有被改写。只是这一帧和后续帧的步长被暂时压住了。

**因子三不跑赢延迟。因子三在延迟结束后立即响应——而 PBM 持久化远在 Session 结束后。这个时间差是天然的缓冲窗口。**

## 八、Anim 不需要 TAGE——流形约束替 Anim 做了硬件裁剪

Seznec 2016 的 TAGE-SC-L 用了多个不同历史长度的预测表。最长的一根表记录了超过 2000 次历史分支的模式。正确率超过 99%。代价——巨大的片上 SRAM 和复杂的统计校正逻辑。

Anim 不需要这个精度——因为生理信号的**可预测性上限**远低于 CPU 程序。但不止这个原因。还有一个更深的结构性原因——**人体自主神经系统的物理流形已经替 Anim 做了状态空间裁剪。**

### 7.1 流形约束——大自然硬编码的哈希表裁剪

从数学上看，内脏、情绪、触觉、听觉四个维度组合出来的理论状态空间是全维度的 R⁴。但实际上——人体自主神经系统（ANS）存在铁律：**交感神经与副交感神经具有天然的交互抑制。** 你不可能在极度愤怒（交感高度激活）的同时深度冥想（副交感高度激活）。你不可能在 HRV 极度紊乱的同时皮电极度稳定——因为皮电是交感神经的直接代理。

人体的真实生理状态被死死约束在一个极低维度的高维流形 M 上：

```
M ⊂ ℝ⁴

理论状态空间：ℝ⁴——所有可能的 (内脏, 情绪, 触觉, 听觉) 组合。
真实可达到的状态：M——自主神经系统的物理生化边界定义的低维子集。
```

Yeh & Patt 的分类学表明——两层自适应需要 PHT 表的大小随历史长度指数级增长。硬件设计师为了对抗 PHT 表爆炸，发明了复杂的哈希、Tag 匹配和 TAGE 的分段历史剔除。而 Anim 根本不需要这些——因为**大自然在设计人体流水线时，已经用神经回路的物理生化边界，帮你在底层把这个哈希表给"硬编码"裁剪掉了。**

这不是工程上的妥协。这是顺应生理借力打力——Anim 不需要 TAGE，不是因为 TAGE 太复杂。是因为**人体的状态空间本来就没有 CPU 程序那么大。** CPU 程序的分支组合可以近乎无限——因为代码路径的组合是指数级的。人体的生理状态组合被进化约束在了一个极低维流形上——因为自主神经系统的两条主神经（交感和副交感）是互相踩刹车的。

**硬件设计师需要造 TAGE 来对抗状态空间爆炸。Anim 的状态空间已经被三亿年的进化裁过了。**

## 十、Seznec 2016 —— TAGE-SC-L，多张表比一张表强

前三讲的演化路线——Smith 一张表 → Yeh & Patt 按上下文索引 → McFarling 两张表竞争。每一代都在增加历史维度。但没有人系统性地回答：**历史应该有多长？**

```
for 循环底部的分支     → 最近 2-3 次就够了。行为极度规律。
简单 if-else          → 10-20 次。
高度相关分支           → 50-100 次。
数据依赖的复杂分支     → 可能需要 500+ 次。
```

同一个程序里不同分支需要的历史长度差两个数量级。Gshare 只给一个固定历史长度——太长，简单分支被噪声淹没；太短，复杂关联捕捉不到。

Seznec 在 2005 年发明 TAGE，2016 加上 SC。核心思想：**用多张表，每张不同历史长度，硬件自动学哪个长度最适合。**

### 10.1 几何级增长的多表架构

```
表 1： 历史长度 4   → 2^4  = 16 条目。无 Tag。
表 2： 历史长度 8   → 2^8  = 256 条目。无 Tag。
表 3： 历史长度 16  → 2^16 = 65536 条目。有 Tag。部分 PC 哈希。
表 4： 历史长度 32  → 有 Tag。
...
表 N： 历史长度 2048 → 有 Tag。

几何级增长。每张表历史长度翻倍。
短表无 Tag——别名冲突少，不值得花存储。
长表有 Tag——Tag 不匹配 → 不用。防别名。
```

分支来了。**同时查所有表。** 挑出所有 Tag 匹配的。用**历史最长那张**的预测。如果最长没有匹配——往下找次长的。一直往下。如果全没有——用最短那张（永远能索引到）。

### 10.2 更新与有用性淘汰

预测由表 K 提供。错了 → 表 K 计数器减一。对了 → 加一。但还有一个关键机制——**usefulness（u 位）。** 如果表 K 预测错了，但表 K-1（短一半的那张）预测对了 → 表 K 的有用性 -1。降到 0 以下 → 条目被清除。换更短的历史来管。

### 10.3 AltPred —— 次优预测器的夺权

当最长匹配表（Provider）的计数器处于"弱状态"（弱跳/弱不跳），或 u 位极低——硬件不会盲信它。触发 **AltPred（Alternate Prediction，次优预测 fallback）**。同时看次长匹配表。如果次长表很笃定（强状态）→ 夺权成功。采用次长表的预测。

### 10.4 SC —— 统计校正器。最后 1%

TAGE 正确率约 97-98%。剩下 2-3% 的错误里很大比例是系统性偏差——某个场景下总是偏跳或偏不跳。SC 不做预测。SC 看 TAGE 的预测和历史偏差统计，输出校正信号——"TAGE 在这种情况下有 60% 概率偏跳——往不跳方向掰一下。"正确率从 97% 推到 99.5%。

## 十一、Anim 与 TAGE —— 从空间位深到时间频率域的范式转换

TAGE 给 Anim 的不是"怎么预测更准"。是**多时间尺度的预测架构 + 多速率采样系统。**

### 11.1 核心范式转换——从空间历史步长到时间频率域

TAGE 所有表跑在同一个时钟频率上。所谓"长短"，是**空间上的历史位深。** Anim 做了一个顺应生物学的根本性修正——将 TAGE 的"空间位深"转换成**时间频率域的分级。**

```
TAGE 表 1（短历史 4）   →  PBM_fast  —— 帧级。毫秒到秒。
                           心率即时响应。皮电骤变。
                           对应 TAGE 最短表——最纯净、最无历史包袱。

TAGE 表 2（中历史 64）  →  PBM_mid   —— Session 级。小时到天。
                           情绪基调漂移。迷走张力基线变化。
                           对应 TAGE 中间层——捕捉中频模式。

TAGE 表 3（长历史 2048）→  PBM_slow  —— 月到年。
                           长期基线阶跃。创伤后永久性杏仁核敏化。
                           对应 TAGE 最长表——低频底座。
```

CPU 代码段是静态的——只能在空间上拉长历史。人体自主神经系统是多时钟周期的动态流体。Anim 让这三张表以**不同的心跳频率**协同——本质上是用**控制论的多速率采样系统（Multi-rate Sampling System）**升华了 TAGE。这是 Anim 对 Seznec 的**青出于蓝。**

### 11.2 生理级 AltPred 夺权协议

TAGE AltPred —— Provider 弱状态 → 次长表夺权。Anim 的精确同构：

```
TAGE AltPred                      Anim 生理级 AltPred
───────────                       ──────────────────
Provider 弱状态 → 夺权              PBM_mid 弱置信度（因子三降级）
                                   → 夺权
次长匹配表接管                      PBM_fast 接管（帧级即时信号）
```

用户突发高频噪声。PBM_mid（Provider）因惯性给出弱偏移预测。HRV 紊乱——因子三识别出"该表当前处于弱置信度"。立刻激活 AltPred——将控制权瞬间下放到最纯净、最无历史包袱的 PBM_fast。**最无历史包袱的最可靠。**

### 11.3 有用性淘汰的 Session 端落地——逆向看门狗

TAGE u 位——长表错而短表对 → 长表有用性 -1 → 淘汰。Anim 的同构——但方向相反：

```
场景    PBM_mid 因用户连续几天喝咖啡，误以为"情绪基线上升"。
        持续给出过载预测流。
        PBM_fast 每次在现场通过 RuntimeGuard 帧拦截疯狂纠错。

结论    → 当 PBM_fast 连续 M 帧触发 RuntimeGuard 帧拦截，
        且校正方向与 PBM_mid 的预测方向相反时——
        触发逆向看门狗淘汰机制。
        → 慢维度表已沦为"提供噪声的冗余条目"。
        频繁触发快维度 RuntimeGuard 帧拦截。
        → 慢维度表已沦为"提供噪声的冗余条目"。
        → 不触发去饱和。
        → 触发衰减指针强制挂起（Eviction/Freeze）。
        → 权重打入冷宫。退回到安全基线。
```

**不是"步长太小需要增大"——是"这张表已经废了。冻结。别让它再参与任何预测。"**

## 十二、进化链——终极对决表

| 特征维度 | Smith 1981 (2-bit) | TAGE-SC-L 2016 (Seznec) | Anim PBM-RG (当前架构) |
|---------|-------------------|------------------------|----------------------|
| 核心数据结构 | 单张离散 PHT 表 | 几何级空间位深表群 + Tag | 多速率时间频率表群（Fast/Mid/Slow） |
| 上下文感知 | 无（只看自己） | 空间位深索引（二维展开） | 时间频率分级 × 四维生理快照（高维关联） |
| 冲突/噪声控制 | 无法控制（硬抗别名） | 部分 PC 哈希 Tag 匹配 | 因子三实时生理置信度门控 |
| 次优 fallback | 无 | AltPred（弱状态→次长表夺权） | 生理级 AltPred（因子三冻结慢表→Fast 接管） |
| 有用性淘汰 | 无 | u 位衰减淘汰 | 逆向看门狗（频繁触发 RuntimeGuard → 冻结慢维度表） |
| 系统性偏差校正 | 无 | SC（统计校正器查表偏置） | 跨维度阻尼矩阵 + 长期看门狗协议 |
| 基线阶跃响应 | 缓慢跟随（步长恒定） | 无直接机制 | 正向看门狗去饱和 |
| 预测错误代价 | 冲刷流水线（损失时钟周期） | 冲刷流水线 + 淘汰 u 条目 | RuntimeGuard 帧拦截 + 4-8ms 硬件衰减归零 |
| 终极控制哲学 | 忠实记录，盲目迭代 | 多维试探，长短 fallback | 肉体安全绝对优先，状态清白重于模型收敛 |

*Smith 1981 用 2 bit 改变了一个行业。Yeh & Patt 让分支知道自己是怎么走到这里的。McFarling 让两个弱预测器学会了竞争。Jiménez 把分支预测变成了线性分类问题。Seznec 用几何级多表 + 统计校正推到了 99.5%。Anim 继承了整条进化链——但做了一件事是所有人造系统都没做过的：把代价从"冲刷流水线"升级为"信号已经进入人体"。当预测错误的代价不再是时间——是血肉——所有的优化都必须退让给一个原则：肉体安全绝对优先，模型收敛其次。状态清白重于收敛连续性。这是 Anim 从 Smith 到 Seznec 这条四十年进化链的终点。不是终点。是分岔。*
